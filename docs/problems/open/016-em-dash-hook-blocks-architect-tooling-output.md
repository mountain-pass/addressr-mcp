# Problem 016: em-dash pre-commit hook blocks architect-tooling output

**Status**: Open
**Reported**: 2026-06-03
**Priority**: 3 (Medium) - Impact: 3 x Likelihood: 1 (deferred - re-rate at next /wr-itil:review-problems)
**Origin**: internal
**Effort**: M (deferred - re-rate at next /wr-itil:review-problems)
**Type**: technical

## Description

The em-dash pre-commit hook (P008, `scripts/check-em-dashes.sh` via lint-staged) blocks auto-generated and upstream-templated markdown that legitimately contains U+2014.

Hit 2026-06-03 committing ADR-006: the `/wr-architect:capture-adr` skeleton template emits em-dashes (frontmatter sentinel `[unspecified (em-dash) fill at canonical review]`, deferred-section pointers) AND the `wr-architect-generate-decisions-compendium` generator emits em-dashes (`5 ADRs total (em-dash) 5 in-force`). `check-em-dashes.sh` flagged 12 + 9 em-dashes; had to run `perl -CSD -i -pe 's/U+2014/-/g'` on both files before the commit would pass.

This will recur on EVERY future `/wr-architect:capture-adr`, `/wr-architect:create-adr`, and any decisions-compendium refresh, because the upstream architect tooling hardcodes em-dashes in its output. The conflict is between two governance tools shipped in the same session (the em-dash hook from P008, and the architect ADR tooling from `@windyroad/agent-plugins`).

## Symptoms

- `git commit` blocked by lint-staged running `scripts/check-em-dashes.sh` on staged `docs/decisions/*.md` after any `/wr-architect:capture-adr` / `/wr-architect:create-adr` invocation.
- The `docs/decisions/README.md` compendium (regenerated by `wr-architect-generate-decisions-compendium` per ADR-077) emits em-dashes in its summary lines.
- Manual `perl -CSD -i -pe 's/\x{2014}/-/g'` de-em-dashing is the current workaround, repeated each time.

## Workaround

After any architect ADR-tooling invocation, run `perl -CSD -i -pe 's/\x{2014}/-/g' docs/decisions/<NNN>-*.md docs/decisions/README.md` before committing. Or use `git commit --no-verify` (the em-dash hook has the `--no-verify` escape hatch by design for genuine-em-dash contexts), but that also bypasses any other lint-staged checks.

## Root Cause Analysis

### Suspected Root Cause

Two governance tools with incompatible conventions:
1. P008's `scripts/check-em-dashes.sh` enforces the project's no-em-dash policy on all staged `*.md` (it already carries a skip-list entry for `docs/problems/README-history.md` per P134).
2. The `@windyroad` architect plugin's ADR skeleton template + `wr-architect-generate-decisions-compendium` generator hardcode em-dashes in their emitted markdown.

### Fix Strategy

Two fix shapes:

1. **Local (lightest, partial)**: extend `scripts/check-em-dashes.sh` skip-list (it already skips `README-history.md`) to also skip `docs/decisions/README.md` (the auto-generated compendium). This does NOT cover the ADR skeleton bodies, which are hand-editable and where the project DOES want the no-em-dash policy enforced - so a blanket `docs/decisions/` skip would let hand-authored em-dashes into ADR prose. Skip only the generated compendium, not the ADR bodies.

2. **Upstream (better, complete)**: report to `@windyroad/agent-plugins` so the `capture-adr` / `create-adr` templates + the compendium generator respect a project em-dash policy (or default to hyphens). This eliminates the conflict at the source for all adopter projects with an em-dash policy.
